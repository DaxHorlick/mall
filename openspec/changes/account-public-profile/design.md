# Design

## Context

账号页是 `src/pages/account/index.tsx` 里的 `AccountPage`。当前用户来自内存会话，字段只有 id、username、nickname、avatar_url、phone、email、status、roles、created_at。`PUT /v1/users/me/profile` 可以提交简介，但当前用户响应不带回简介、横幅、社交链接、粉丝或作品。页面下面已有资料、密码、登录设备、第三方身份和退出，请求与校验都写在这个函数里。见 `specs/account-profile/spec.md`。

## Goals / Non-Goals

**Goals:**

- 在现有函数的返回结果顶部放公开主页，只使用当前用户里对得上的字段。
- 缺数据的位置用明确的空状态，不发新请求。
- 原有五个操作分区和它们的提交逻辑保持不动。

**Non-Goals:**

- 不新增组件文件、路由、接口、字体或图片。
- 不把关注、分享、搜索或筛选做成可点击控件。
- 不改登录、注册、404、顶栏和页脚。

## Decisions

1. **主页写在 `AccountPage` 的返回结果里，不拆新组件。** 这块只在账号页使用。备选是抽出 `ProfileHeader`，但没有第二处调用。
2. **标题改为昵称。** 用现有的 `text-4xl font-normal`，不再用「账号」作主标题。用户名显示为 `@` 加 `username`；`username` 为空时显示「未设置」，不加 `@`。加入时间继续用页面里已有的 UTC 格式，标签为「加入」。
3. **横幅是没有图片的圆角色带。** 用近黑纯色，不用照片。有 `avatar_url` 时在色带下方放圆形图片；没有则只留圆形空位，不放 `img`。
4. **空状态写明没有数据，不写数量 0。** 简介、社交链接、粉丝、作品分别写「当前没有简介数据」「当前没有社交链接数据」「当前没有粉丝数据」「当前没有作品数据」。简介即使曾被保存也不会从当前用户返回，所以不能写成「还没有简介」。
5. **只读账号字段移到主页和「资料」之间。** 手机、邮箱、状态、角色、用户 ID 仍用现在的定义列表，不再放在页面最上方。资料、密码、登录设备、第三方身份、退出的标题和表单原样保留。

## Risks / Trade-offs

- [未归档的 `restyle-auth-pages` 要求账号页以原表单开头] → 这次只替换开头。五个操作分区的顺序和主按钮样式不动。
- [空状态可能被理解成用户确实没有简介或粉丝] → 文案写「当前没有…数据」，不写 0，也不提供编辑这些缺口的新字段。
- [主页加在长表单上面，账号操作需要向下滚动] → 不拆路由。认证文档要求这些操作留在账号页。

## Migration Plan

只改前端页面。刷新即可看到。回退时恢复 `src/pages/account/index.tsx`。没有数据迁移。
