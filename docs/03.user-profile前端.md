# UserProfile 前端实现提示词

后端用户资料、搜索和关注接口已经完成。按下面的契约做前端，不要改接口路径和字段名，不要写测试代码。

技术栈跟当前前端项目保持一致。如果项目里已有请求封装、登录态、布局和组件，直接复用，不要另起一套。

本次只做用户资料相关页面，不做到登录注册、收货地址、角色管理和后台管理。

## 一、接入约定

接口基址：`/api/v1`

除健康检查外，下面所有接口都要登录。请求头：

```http
Authorization: Bearer <access_token>
Content-Type: application/json
```

访问令牌来自现有登录接口 `POST /api/v1/auth/login` 或刷新接口 `POST /api/v1/auth/refresh` 返回的 `access_token`。当前用户身份只放在令牌里，不要在 body 或 query 里传当前用户 id。

统一响应：

```json
{
  "code": 0,
  "message": "ok",
  "data": {},
  "request_id": "可选"
}
```

判断成功只看 `code === 0`。失败时 `message` 是给用户看的中文，`data` 通常没有。`request_id` 有就带上，没有就忽略。

常见错误：

| HTTP | code | message | 前端处理 |
|---|---|---|---|
| 400 | 40000 | 具体原因，见各接口 | 停在当前页，展示 message |
| 401 | 40100 | 未登录或登录已失效 | 清登录态，去登录页 |
| 403 | 40300 | 账号不可用 / 没有权限 / 该用户已禁用 / 该用户已冻结 | 展示 message，不要重试提交 |
| 404 | 40400 | 用户不存在 | 展示空状态或 message |
| 500 | 50000 | 内部错误 | 展示 message |

性别：`0` 未知，`1` 男，`2` 女，`3` 其他。

账号状态：`0` 禁用，`1` 正常，`2` 冻结。只有「我的资料」会返回 `status`。

## 二、页面

做这四块，路由名可以按项目习惯，数据必须按下面的接口来。

1. 我的资料：查看和编辑当前用户。
2. 用户主页：查看某个用户的公开资料，并能关注或取消关注。
3. 用户搜索：按用户名或昵称搜人，结果能进主页、能关注。
4. 关注和粉丝：我的列表，以及某个用户主页上的列表。

从「我的」进入编辑页。从搜索、关注、粉丝进入 `/users/:user_id` 这种主页。看自己的主页时，关注按钮不要显示成「已关注」，后端会固定返回 `is_following: false`。可以显示「编辑资料」。

## 三、我的资料

### 获取

`GET /api/v1/users/me`

`data`：

```json
{
  "user_id": 10001,
  "username": "user001",
  "user_no": "a048273",
  "email": "user@example.com",
  "phone": "13800000000",
  "status": 1,
  "nickname": "昵称",
  "avatar": "头像URL",
  "cover_image": "封面URL",
  "bio": "个人简介",
  "gender": 0,
  "birthday": "2000-01-01",
  "location": "广东深圳",
  "following_count": 4,
  "followers_count": 0,
  "post_count": 9
}
```

`email`、`phone` 没有绑定就不返回。`birthday` 没有时是空字符串。`username`、`user_no`、`email`、`phone`、`status` 只展示，不能在这个页面修改。`user_no` 是后端注册时生成的用户号，格式为 `a` 加 6 位数字，用来让别人精确找到这个用户。

关注数、粉丝数可点击，分别进入自己的关注列表和粉丝列表。

### 保存

`PUT /api/v1/users/me/profile`

只提交改过的字段。没改的字段不要出现在 JSON 里，后端会保留原值。

```json
{
  "nickname": "昵称",
  "avatar": "头像URL",
  "cover_image": "封面URL",
  "bio": "个人简介",
  "gender": 1,
  "birthday": "2000-01-01",
  "location": "广东深圳"
}
```

清空某个文本字段时，传空字符串，例如 `"nickname": ""`、`"birthday": ""`。性别可以改回 `0`。

不要提交 `user_id`、`username`、`user_no`、`email`、`phone`、`password`、`status`。后端会忽略这些字段，前端也不要做修改入口。

限制：

- 昵称最多 50 个字
- 头像地址、封面地址、个人简介最多 500 个字
- 所在地最多 100 个字
- 性别只能是 0、1、2、3
- 生日用 `YYYY-MM-DD`

成功后用返回的 `data` 更新页面，它和「获取我的资料」是同一结构。失败时展示 `message`，不要把未通过校验的内容写进本地缓存。

头像和封面这一步只保存 URL。上传文件不在本次范围；项目里如果已有上传能力，上传完成后把得到的 URL 填进这两个字段。

## 四、用户主页

`GET /api/v1/users/{user_id}`

`user_id` 是路径里的数字。非数字或小于等于 0 时，前端直接提示参数错误，不必发请求。

`data`：

```json
{
  "user_id": 10001,
  "username": "user001",
  "user_no": "a048273",
  "nickname": "用户昵称",
  "avatar": "https://example.com/avatar.jpg",
  "cover_image": "https://example.com/cover.jpg",
  "bio": "个人简介",
  "gender": 0,
  "location": "深圳",
  "following_count": 100,
  "followers_count": 200,
  "post_count": 50,
  "is_following": false
}
```

这里没有邮箱、手机号、生日、账号状态和密码。不要从别处拼这些敏感字段。

页面展示封面、头像、昵称、用户名、简介、性别、所在地、关注数、粉丝数、动态数。关注数和粉丝数进入对应列表。

`user_id` 等于当前登录用户时：

- 不显示关注按钮
- 显示进入编辑资料
- 忽略 `is_following`

否则按 `is_following` 显示「关注」或「已关注」。

关注：`POST /api/v1/users/{user_id}/follow`

取消关注：`DELETE /api/v1/users/{user_id}/follow`

两个接口都没有请求体。成功时 `data` 为：

```json
{ "is_following": true }
```

取消关注成功时 `is_following` 为 `false`。重复关注、重复取消都算成功，用返回值更新按钮，不要因为本地觉得已经关注过就不再请求。

关注自己会返回 400，`message` 为「不能关注自己」。用户不存在为 404「用户不存在」。对方被禁用或冻结为 403，「该用户已禁用」或「该用户已冻结」。这些情况下不要改本地关注数。

关注或取消成功后，重新拉一次主页，让关注数和粉丝数跟服务器一致。

可选的轻量状态接口：`GET /api/v1/users/{user_id}/follow-status`，`data` 只有 `is_following`。主页已经带了这个字段，列表项需要单独刷新时再用。

## 五、搜索

`GET /api/v1/users/search?keyword={keyword}&page=1&page_size=20`

`keyword` 必填，去掉首尾空格后不能为空，最多 50 个字。空关键词不要发请求，提示「请输入搜索关键词」。

`page` 从 1 开始。`page_size` 默认 20，最大 100。

`data`：

```json
{
  "list": [
    {
      "user_id": 10001,
      "username": "user001",
      "user_no": "a048273",
      "nickname": "昵称",
      "avatar": "头像URL",
      "bio": "个人简介",
      "is_following": false
    }
  ],
  "total": 100,
  "page": 1,
  "page_size": 20,
  "total_pages": 5
}
```

`list` 为空时是 `[]`，不要按 `null` 处理。搜索同时匹配用户名、用户号和昵称，大小写不敏感。输入完整用户号 `a048273` 可以找到对应用户。只显示正常用户。`%` 和 `_` 就是普通字符，不要自己拼通配符。

每一项可以进主页。关注按钮用该项的 `is_following`。点自己时不要发关注请求。关注成功后把该项改成已关注；取消后改回未关注。

分页用返回的 `page`、`total_pages`。没有下一页就停止加载。

## 六、关注列表和粉丝列表

我的关注：`GET /api/v1/users/me/following`

我的粉丝：`GET /api/v1/users/me/followers`

某人的关注：`GET /api/v1/users/{user_id}/following`

某人的粉丝：`GET /api/v1/users/{user_id}/followers`

查询参数同样是 `page`、`page_size`。返回结构和搜索一样，`list` 里也是上面的用户卡片。

`is_following` 表示当前登录用户是否关注这个人，不是列表主人是否关注他。列表里出现自己时，这个值是 `false`。

卡片点击进主页。列表主人不存在时展示「用户不存在」。

## 七、交互要求

- 列表和主页加载时有加载状态，失败时展示 `message`，并允许重试。
- 关注按钮请求进行中时不可重复点击。
- 昵称、简介、所在地、头像、封面、生日在提交前按上面的长度和格式校验，能在本地拦住的错误不要等接口返回。
- 性别用四个明确选项，不要让用户输入任意数字。
- 日期选择器输出 `YYYY-MM-DD`。清空生日时提交空字符串。
- 数字 `user_id` 用字符串保存也可以，展示和请求时不要丢精度。后端是 int64。
- 封面、头像地址为空时用默认占位，不要把空字符串当成图片地址去请求。
- 401 统一走现有登录失效处理。403 只展示文案。

## 八、不要做的事

- 不写测试代码。
- 不实现注册、登录、改密码、退出。
- 不实现收货地址、动态发布、后台管理。
- 不在前端保存密码、令牌以外的敏感凭证。
- 不根据 query 或本地输入伪造当前用户 id。
- 不展示邮箱和手机号到别人的主页、搜索结果、关注和粉丝列表。
