# 代码流程

这份说明按「人在页面上做了什么，代码接着走到哪个文件」来写。不会前端也可以顺着看。

先记住三件事：

- 浏览器地址决定看见哪一页。对照表在 `src/router/index.tsx`。
- 一个页面就是一个以 `Page` 结尾的函数，都在 `src/pages`。做衣服的页面在 `src/pages/designer`。
- 有的数据会问服务器，有的只留在这台浏览器里。下面每条流程都会写明是哪一种。

## 程序从哪进来

1. 浏览器打开网站，先读 `index.html`。里面有一个空盒子 `<div id="root">`，并加载 `src/main.tsx`。
2. `src/main.tsx` 把整个应用画进这个空盒子，入口组件是 `App`。
3. `src/App.tsx` 先定好中文或英文，再准备接口结果的临时缓存，最后把网址交给路由。
4. `src/router/index.tsx` 按网址选出要显示的页面。

页面外面还有一层 `src/layouts/MainLayout.tsx`：上面是顶栏，中间是当前页面，下面是底栏。这一层同时检查有没有登录。做衣服的 `/designer` 也走这一层。

## 打开网站时先检查登录

登录状态放在 `src/auth/session.ts`。

浏览器里记着三样东西：

| 名字 | 放在哪 | 关掉浏览器以后 |
| --- | --- | --- |
| `dezajn.refresh_token` | 长期存储 | 还在，用来换新的访问令牌 |
| `dezajn.access_token` | 这次打开的标签 | 没了 |
| `dezajn.user` | 这次打开的标签 | 没了 |

`MainLayout` 一出现就调用 `src/auth/bootstrap.ts` 里的 `bootstrapSession`：

1. 两样令牌都没有，当成没登录。
2. 只有长期令牌，就向服务器 `POST /v1/auth/refresh` 换一张新的访问令牌。
3. 有访问令牌、标签里还有用户资料，直接当成已登录。
4. 有访问令牌、没有用户资料，就向服务器要 `GET /v1/users/me`。

没登录时，只能停在这几个地址：`/`、`/login`、`/register`、`/forgot-password`、`/reset-password`。打开别的地址，会被送到 `/login`。

已经登录还停在登录页或注册页，会被送到 `/profile`。

所有发给服务器的请求都从 `src/api/client.ts` 的 `request` 出去。需要登录的请求会带上访问令牌。开发时接口地址来自环境变量 `VITE_API_BASE_URL`，本机后端是 `http://localhost:8080`。

## 看首页

地址：`/`

文件：`src/pages/home/index.tsx` 的 `HomePage`

首页可以不登录。商品名单写在 `src/shop/products.ts`，页面直接拿这份名单来画，不向服务器要商品。

从这里能去两个地方：逛商品是 `/explore`，开始做衣服是 `/designer`。

## 看商品、放进购物袋、结账

这条线的商品、购物袋、订单都在浏览器内存里，刷新页面就没了，也不会发给服务器。

1. `/explore` 打开 `src/pages/explore/index.tsx`。它把 `products` 里的每件商品画成一张卡片。
2. 点一张卡片，地址变成 `/products/某一件的编号`，打开 `src/pages/product/index.tsx`。
3. 点加入购物袋，调用 `src/shop/store.ts` 的 `addLine`，把这件商品的编号记进 `lines`，然后地址变成 `/bag`。
4. `/bag` 是 `src/pages/bag/index.tsx`。删一件商品调用 `removeLine`。
5. 去结账打开 `/checkout`，文件是 `src/pages/checkout/index.tsx`。购物袋是空的，就退回 `/bag`。
6. 点下单调用 `placeOrder`。它生成一张订单，订单号固定是 `DZ-1026`，然后清空购物袋，地址变成 `/order`。
7. `/order` 是 `src/pages/order/index.tsx`。内存里没有订单，就退回 `/bag`。

## 社区里给商品投票

地址：`/community`

文件：`src/pages/community/index.tsx`

点投票调用 `src/shop/store.ts` 的 `toggleVote`。投过的编号记在内存里的 `votes`，刷新就没了。页面上的「开始创作」去 `/designer`。

## 注册、登录、找回密码

这些都会问服务器。

1. `/register` 打开 `src/pages/register/index.tsx`。提交后 `POST /v1/auth/register`，成功就去 `/login`。
2. `/login` 打开 `src/pages/login/index.tsx`。提交后 `POST /v1/auth/login`。服务器返回访问令牌、长期令牌和用户资料，`signIn` 把它们写进浏览器。接着 `MainLayout` 发现已经登录，把人送到 `/profile`。
3. `/forgot-password` 打开 `src/pages/forgot-password/index.tsx`，提交 `POST /v1/auth/forgot-password`。
4. `/reset-password` 打开 `src/pages/reset-password/index.tsx`，提交 `POST /v1/auth/reset-password`，成功后回到 `/login`。

## 账号、地址、找人

这些页面必须已经登录，数据来自服务器。

1. `/profile` 打开 `src/pages/account/index.tsx`。它调用 `src/profile/api.ts` 的 `fetchMyProfile`，向服务器要当前用户，再把新资料写回登录状态。
2. `/profile/edit` 打开 `src/pages/account/edit.tsx`，改完回到 `/profile`。
3. `/profile/addresses` 打开 `src/pages/account/addresses.tsx`，请求 `GET /v1/users/me/addresses`。
4. 新建地址是 `/profile/addresses/new`，改某一条是 `/profile/addresses/地址编号`。两个地址都用 `src/pages/account/address-form.tsx`。保存后回到地址列表。
5. 我关注的人是 `/profile/following`，关注我的人是 `/profile/followers`，都用 `src/pages/user/people.tsx`。
6. `/search` 打开 `src/pages/user/search.tsx`，按关键字找用户。
7. `/users/用户编号` 打开 `src/pages/user/index.tsx`，看这个人的主页。他的关注和粉丝也走 `people.tsx`。

## 做一件衣服

地址：`/designer`。保存过之后变成 `/designer/这份设计的编号`。

必须已经登录。没登录时，`MainLayout` 会把人送到 `/login`。页面文件是 `src/pages/designer/index.tsx` 的 `DesignerPage`，它只检查地址里的设计编号在不在这台浏览器里。

页面分成两块，都写在 `src/pages/designer/editor.tsx`：

- 左边选款式、颜色，管理自己的图库。
- 右边是衣服大图。大图上方有撤销、重做、正面或背面、衣服区域，最右边是「保存为设计」。

款式和颜色向服务器要。`src/pages/designer/editor.tsx` 打开时请求 `GET /v1/clothing/styles` 和 `GET /v1/clothing/colors`，按钮上的名字和色块用接口返回的。平面轮廓仍由 `src/designer/draw.ts` 画：T 恤和圆领卫衣用圆领，卫衣用连帽。

### 上传一张图

图库是当前登录用户自己的，存在服务器上。打开设计器时，`src/pages/designer/editor.tsx` 请求 `GET /v1/users/me/images` 的第一页。超过一页时，点「加载更多」再要下一页，接到现有列表后面。

1. 左边点「上传图片」，只接受 PNG、JPG、WebP，且不超过 8MB。
2. 选中的文件交给 `src/designer/api.ts` 的 `uploadLibraryImage`，`POST /v1/users/me/images`。成功后插到列表最前面。
3. 点缩略图上的「删除」，调用 `deleteLibraryImage`，只从列表去掉这一张。
4. 再点这张缩略图，`addLayer` 把它贴到当前选中的衣服区域。图层编号由设计器自己生成，衣服上已经贴好的图案不跟着图库删除。

试透明效果可以用 `public/samples/transparent.png`。浏览器里的地址是 `/samples/transparent.png`。

### 衣服大图怎么画出来

`src/pages/designer/board.tsx` 拿到一块画布：

1. 先铺白底。
2. `src/designer/draw.ts` 按款式、正反面、颜色画出衣服。
3. 再画出能印图案的虚线框。
4. 最后把这一面已经贴上的图案画上去。透明的地方会露出衣服颜色。

在画布上拖图案，会改这张图案的位置。换颜色、换款式、挪图案之前，会先记一笔，所以可以撤销。撤销最多留 40 笔。换正反面不记入撤销。

### 保存

点「保存为设计」，`src/designer/design.ts` 的 `saveDesign` 把款式、颜色和图案写两处：

- 当前这次打开的内存。
- 这台浏览器的长期存储，键名是 `dezajn.saved-designs`。

第一次保存会换到 `/designer/新编号`。再次打开这个地址时，`EditorLayout` 用 `getDesign` 把这份设计画回去。

这里没有把设计发给后端。地址对应的记录在这台浏览器里找不到时，页面会提示「这份设计还没有保存在服务器上」，下面仍是本地设计器。

## 地址对不上任何页面

`src/router/index.tsx` 最后一条 `*` 交给 `src/pages/not-found/index.tsx`。已登录回去账号页，没登录去登录页。

## 文件夹对照

| 文件夹 | 里面是什么 |
| --- | --- |
| `src/main.tsx`、`src/App.tsx` | 程序入口 |
| `src/router` | 网址和页面的对照表 |
| `src/layouts` | 顶栏、底栏，以及登录检查 |
| `src/pages` | 首页、商品、购物袋、账号、登录，以及做衣服的页面和编辑界面 |
| `src/designer` | 款式、本地保存的设计、画布上怎么画衣服 |
| `src/auth` | 登录状态和打开网站时的恢复 |
| `src/api` | 发请求给服务器 |
| `src/shop` | 写死的商品，以及只存在内存里的购物袋和订单 |
| `src/profile` | 向服务器要个人资料和地址 |
| `src/i18n` | 中文和英文文案 |
| `src/components` | 顶栏、底栏、商品卡片这些多处会用到的画面 |
| `public/samples` | 可以直接用网址打开的样图 |

## 自己顺着代码看的时候

1. 先打开 `src/router/index.tsx`，找到网址旁边的页面名字。
2. 打开那个页面文件，从上往下看函数里的步骤。
3. 按钮旁边的 `onClick` 就是点击后要做的事。它多半会调用 `src/shop/store.ts`、`src/auth/session.ts`，或者 `request(...)`。
4. 看到 `request` 的那一行，引号里的路径就是发给服务器的接口，例如 `/v1/auth/login`。
