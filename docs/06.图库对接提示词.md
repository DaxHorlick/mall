# 用户图库对接提示词

## 一、任务目标

在现有商城前端 `d:\WORK\mall` 中，把设计器里的「我的图库」从浏览器 `localStorage` 换成下面三个接口。后端已经实现，不要改后端，也不要新起项目。

```text
POST   /api/v1/users/me/images
GET    /api/v1/users/me/images
DELETE /api/v1/users/me/images/{id}
```

图库是当前登录用户自己的图片。上传的图和以后 AI 生图保存的图都在这一份列表里。这次只接上传、列表和删除。不要做 AI 生图页面，也不要做后台管理。

开始前先看：

- `src/api/client.ts` 的 `request`、`toQueryString`、`ApiError`、`getErrorMessage`
- `src/designer/store.ts` 里读写 `dezajn.design-library` 的 `addToLibrary`、`removeFromLibrary`
- `src/pages/designer/editor.tsx` 里「我的图库」和上传按钮
- `src/designer/types.ts` 的 `LibraryImage`

开发环境 `VITE_API_BASE_URL` 是 `/api`。请求路径写成 `/v1/users/me/images`，不要再拼一次 `/api`。图片地址以 `/assets/library/` 开头，现有 Vite 已经把 `/assets` 代理到后端，`<img src>` 直接用返回的 `url`。

## 二、调用约定

三个接口都要登录，传 `auth: true`。未登录得到 `40100`，交给现有刷新和退出流程。

`request<T>()` 已经拆掉 `{ code, message, data }`，函数直接拿到 `data`。失败时用 `getErrorMessage` 显示后端中文。

| HTTP | code | 场景 |
|---|---|---|
| 400 | 40000 | 没选文件、类型不对、超过 8MB、来源参数不对 |
| 401 | 40100 | 未登录或登录失效 |
| 403 | 40300 | 账号不可用 |
| 404 | 40400 | 图片不存在，或不是当前用户的 |
| 500 | 50000 | 内部错误 |

只能上传 PNG、JPG、WebP。其他类型返回「请上传 PNG、JPG 或 WebP 图片」。超过 8MB 返回「图片不能超过 8MB」。空文件返回「请选择图片」。

删除只把图片移出图库。已经贴到衣服上的图层继续用原来的 `url`，不要因为图库里删了就把图层清掉。

## 三、接口

类型放在 `src/designer/api.ts`，或并进现有设计器类型文件。`id` 是数字，不要再当成字符串。

```ts
export type LibraryImage = {
  id: number
  source: 'upload' | 'ai'
  name: string
  url: string
  mime: string
  width: number
  height: number
  file_size: number
  created_at: string
}

export type ImagePage = {
  list: LibraryImage[]
  total: number
  page: number
  page_size: number
  total_pages: number
}
```

`width`、`height` 读不到时是 `0`，WebP 目前就是 `0`。网格用 `object-cover` 显示，不要靠这两个字段排版。

### 1. 上传

`POST /v1/users/me/images`

用 `FormData`，字段名是 `file`。不要手写 `Content-Type`，否则会丢掉浏览器的 `boundary`。`request` 遇到 `FormData` 时不会改成 JSON。

```ts
export function uploadLibraryImage(file: File) {
  const body = new FormData()
  body.append('file', file)
  return request<LibraryImage>('/v1/users/me/images', {
    method: 'POST',
    auth: true,
    body,
  })
}
```

成功的 `data` 就是上面的 `LibraryImage`，`source` 固定是 `upload`。上传成功后把这一条插到列表最前面。

### 2. 列表

`GET /v1/users/me/images`

| 参数 | 说明 |
|---|---|
| source | 可选。`upload` 只看自己上传的，`ai` 只看以后保存的生图。不传返回全部 |
| page | 可选，默认 1 |
| page_size | 可选，默认 20，最大 100 |

```ts
export function fetchLibrary(query: { source?: 'upload' | 'ai'; page?: number; page_size?: number }) {
  return request<ImagePage>(`/v1/users/me/images${toQueryString(query)}`, { auth: true })
}
```

`list` 为空时是 `[]`。按创建时间倒序，新的在前面。设计器打开时请求第一页。这次页面可以只展示第一页；翻页时再请求下一页，接到现有列表后面。

### 3. 删除

`DELETE /v1/users/me/images/{id}`

成功时没有 `data`。只从当前列表去掉这一条。

```ts
export function deleteLibraryImage(id: number) {
  return request<void>(`/v1/users/me/images/${id}`, {
    method: 'DELETE',
    auth: true,
  })
}
```

别人的图片或已经删掉的图片返回 404，文案是「图片不存在」。

## 四、设计器怎么接

`src/designer/store.ts` 现在把图库写进 `localStorage`，键是 `dezajn.design-library`，最多 24 张，而且只接受 `data:image/`。去掉这段读写。

1. 进入设计器时调用 `fetchLibrary({ page: 1 })`，用返回的 `list` 渲染「我的图库」。
2. 上传按钮仍限制 PNG、JPG、WebP。选中文件后调用 `uploadLibraryImage`，不要再用 `FileReader` 把图片转成 data URL。
3. 点击一张图，继续调用现有 `addLayer`。`imageUrl` 用接口返回的 `url`，`name` 用接口返回的 `name`。图层自己的 `id` 仍由设计器生成，不要把图库 `id` 当成图层 `id`。
4. 图库上的删除调用 `deleteLibraryImage`。已经贴上的图层保持不动。
5. 失败提示用 `getErrorMessage`。不要再出现「图片保存在这台浏览器里」和「图库空间不够，请先删掉几张图片」。

AI 生图以后会以 `source: "ai"` 出现在同一个列表里。设计器不用区分来源就能选中并贴上。这次不要做筛选开关，除非页面上已经有这个入口。

## 五、不要做的事

1. 不要把图片内容放进 `localStorage` 或设计 JSON。
2. 不要调用服装模型接口来保存贴图。贴图和图库是用户自己的图，款式模型是衣服模板。
3. 不要做 AI 生成、提示词和额度。
4. 不要改 `src/api/client.ts` 的响应拆包。上传必须走 `FormData`。
5. 不要在删除图库图片时删除衣服上已经贴好的图层。
