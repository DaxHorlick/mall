# 收货地址前端实现提示词

后端收货地址接口已经完成。按下面的契约做前端，不要改接口路径和字段名，不要写测试代码。

技术栈跟当前前端项目保持一致。如果项目里已有请求封装、登录态、布局和组件，直接复用，不要另起一套。

本次只做当前用户的收货地址，不做到登录注册、个人资料、关注、角色管理和后台管理。

## 一、接入约定

接口基址：`/api/v1`

如果请求封装已经把基址写成 `/api`，下面的路径去掉 `/api` 再传。例如调用 `request('/v1/users/me/addresses')`。

全部接口都要登录。请求头：

```http
Authorization: Bearer <access_token>
Content-Type: application/json
```

访问令牌来自现有登录接口 `POST /api/v1/auth/login` 或刷新接口 `POST /api/v1/auth/refresh` 返回的 `access_token`。当前用户只放在令牌里。不要在 body、query 或路径里传 `user_id`。

统一响应：

```json
{
  "code": 0,
  "message": "ok",
  "data": {},
  "request_id": "可选"
}
```

判断成功只看 `code === 0`。失败时 `message` 是给用户看的中文，通常没有 `data`。`request_id` 有就带上，没有就忽略。

常见错误：

| HTTP | code | message | 前端处理 |
|---|---|---|---|
| 400 | 40000 | 具体原因，见各字段 | 停在表单，展示 message |
| 401 | 40100 | 未登录或登录已失效 | 清登录态，去登录页 |
| 403 | 40300 | 账号已禁用 / 账号已冻结 / 账号不可用 / 没有权限 | 展示 message，不要重试提交 |
| 404 | 40400 | 地址不存在 | 回到地址列表，并重新拉取 |
| 409 | 40900 | 默认地址冲突，请重试 | 自动再请求一次；仍失败就展示 message |
| 500 | 50000 | 内部错误 | 展示 message |

地址编号 `address_id` 是 int64。用字符串保存也可以，展示和请求时不要丢精度。

## 二、页面

做这三块，路由名可以按项目习惯。

1. 地址列表：只展示当前登录用户的地址。
2. 新增地址。
3. 编辑地址。

从「我的」进入列表。列表进入新增和编辑。不要做查看别人地址的页面。

列表顺序用接口返回的顺序：默认地址在最前，其余按创建时间从新到旧。不要在前端再排一次。

每条地址展示收货人、手机号、完整地址和默认标记。完整地址按「国家 省 市 区 详细地址」拼接，空的地区段跳过。邮编有值再显示。

每条要有：编辑、删除、设为默认。已经是默认的那条，把「设为默认」显示成已默认，不要再发请求。

## 三、地址对象

新增、修改、设为默认成功后，`data` 都是这一条地址：

```json
{
  "address_id": 1,
  "receiver_name": "张三",
  "phone": "13800138000",
  "country": "中国",
  "province": "广东省",
  "city": "深圳市",
  "district": "南山区",
  "detail_address": "科技园某某大厦 1001 室",
  "postal_code": "518000",
  "is_default": true,
  "created_at": "2026-11-24T05:00:00Z",
  "updated_at": "2026-11-24T05:00:00Z"
}
```

`created_at`、`updated_at` 是 RFC3339 时间。`postal_code` 没有时是空字符串。`is_default` 为 false 时字段也在。

## 四、地址列表

`GET /api/v1/users/me/addresses`

没有分页，没有 query。`data` 是数组。没有地址时是 `[]`，不要按 `null` 处理。

空列表显示空状态，并提供「新增地址」。

## 五、新增地址

`POST /api/v1/users/me/addresses`

请求体：

```json
{
  "receiver_name": "张三",
  "phone": "13800138000",
  "country": "中国",
  "province": "广东省",
  "city": "深圳市",
  "district": "南山区",
  "detail_address": "科技园某某大厦 1001 室",
  "postal_code": "518000",
  "is_default": true
}
```

字段：

| 字段 | 规则 |
|---|---|
| receiver_name | 必填，去掉首尾空格后 1 到 50 个字 |
| phone | 必填。可选一个 `+`，后面 6 到 20 位数字，整段最长 20 个字符 |
| country、province、city、district | 选填，各自最长 50 个字。不填就传空字符串 |
| detail_address | 必填，1 到 255 个字 |
| postal_code | 选填，最长 20 个字。不填传空字符串 |
| is_default | 布尔值。不传时后端按 false |

不要传 `user_id`、`address_id`、`created_at`、`updated_at`。

用户还没有地址时，就算 `is_default` 是 false，这条也会变成默认地址。提交前如果列表是空的，可以提示「将设为默认地址」。成功后用返回的 `is_default`，不要只相信勾选框。

指定为默认时，后端会取消这个用户其他地址的默认状态。成功后重新拉取列表，或把本地其他地址的 `is_default` 改成 false。

## 六、单条地址

`GET /api/v1/users/me/addresses/{address_id}`

编辑页可以用列表里已有的数据，也可以再请求这一条。地址不存在时回列表。

`address_id` 不是正整数时不要发请求。

## 七、修改地址

`PUT /api/v1/users/me/addresses/{address_id}`

这是整份提交，不是局部更新。编辑页要带上全部字段，漏掉的字符串会被当成空。请求体和新增一样。

取消默认时：

- 这是唯一一条地址：后端仍保持默认。成功后以返回的 `is_default` 为准，勾选框要跟着变回去。
- 还有其他地址：后端会把最近创建的另一条设为默认。必须重新拉取列表，不能只改当前这一条。

改成默认时，同样要清掉其他地址的默认标记。

## 八、删除地址

`DELETE /api/v1/users/me/addresses/{address_id}`

删除前要确认。成功时没有 `data`，只要 `code === 0`。成功后重新拉取列表。

删的是默认地址、并且还剩其他地址时，最近创建的那条会变成默认。不要在本地猜哪一条，以重新拉取的结果为准。

地址已经不存在时返回「地址不存在」。这时也刷新列表。

## 九、设为默认

`PUT /api/v1/users/me/addresses/{address_id}/default`

没有请求体。成功后 `data` 是这条地址，`is_default` 为 true。把其他地址的默认标记清掉，或重新拉取列表。

重复把当前默认地址再设一次，后端仍返回成功。按钮在已默认时不要发请求。

## 十、交互要求

- 列表加载时有加载状态。失败展示 `message`，并允许重试。
- 新增、保存、删除、设为默认进行中时，按钮不可重复点击。
- 收货人、手机号、详细地址、地区和邮编在提交前按上面的长度校验。手机号用同一条规则在本地拦住。
- 手机号允许 `+8613800138000` 这种写法，不要写成只接受 11 位大陆号码。
- 地区可以留空。四个地区框不要标成必填。
- 409 时自动重试一次当前操作。第二次仍失败，展示「默认地址冲突，请重试」。
- 401 走现有登录失效处理。403 只展示文案。

## 十一、不要做的事

- 不写测试代码。
- 不实现注册、登录、个人资料、关注和后台管理。
- 不在前端指定地址属于哪个用户。
- 不展示或编辑其他用户的收货地址。
- 不把 `created_at`、`updated_at` 放进提交体。
